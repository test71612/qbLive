# لوحة العمليات (Ops Hub)

أداة داخلية صغيرة تجيب على سؤالين فقط، بسرعة:

1. **من يعمل على هذا الملف الآن، ولماذا؟**
2. **ما الملفات المرتبطة بهذه الصفحة/الميزة؟**

اللوحة **لا تعدّل الشيفرة إطلاقًا**. تقرأ المستودع من GitHub فقط، وتُخزّن عندها الحجوزات والملاحظات والمهام. التعديل يظل يحدث كالمعتاد عبر أدوات الذكاء الاصطناعي و`git`.

## التشغيل من الصفر (٢٠ دقيقة تقريبًا)

### ١) Supabase

1. أنشئ مشروعًا مجانيًا على [supabase.com](https://supabase.com).
2. من **SQL Editor** الصق محتوى `schema.sql` كاملًا ونفّذه.
3. من **Project Settings → API** انسخ: `Project URL`, `anon key`, `service_role key`.

> تنبيه على الخطة المجانية: المشروع يدخل في سبات إذا لم يصله أي طلب لمدة ٧ أيام. أول فتح بعدها يستغرق ثوانٍ إضافية. لا مشكلة لأداة داخلية تُستخدم يوميًا.

### ٢) تطبيق GitHub OAuth

من `GitHub → Settings → Developer settings → OAuth Apps → New OAuth App`:

- **Homepage URL:** `http://localhost:3000` (وبعد النشر: رابط Vercel)
- **Authorization callback URL:** `http://localhost:3000/api/auth/callback`

انسخ `Client ID` و`Client Secret`.

### ٣) متغيرات البيئة

```bash
cp .env.example .env.local
```

واملأ القيم. `SESSION_SECRET` أي نص عشوائي طويل:

```bash
openssl rand -base64 32
```

ضع اسم مستخدمك على GitHub في `ADMIN_GITHUB_USERNAMES` لتحصل على صلاحية المسؤول عند أول دخول.

### ٤) التشغيل

```bash
npm install
npm run dev
```

### ٥) ربط المستودع

بعد أول دخول (كمسؤول)، أضف المستودع:

```bash
curl -X POST http://localhost:3000/api/repos \
  -H 'content-type: application/json' \
  --cookie 'ops_hub_session=<من المتصفح>' \
  -d '{"repo":"owner/name","label":"منصة البث"}'
```

أو أضف صفًا مباشرة في جدول `repos` من Supabase — أسرع.

### ٦) النشر على Vercel

اربط المستودع بـ Vercel، وانسخ نفس متغيرات البيئة، ثم عدّل `APP_URL` ورابط الـ callback في تطبيق OAuth إلى رابط الإنتاج.

### ٧) Webhook التحديث التلقائي

في المستودع الهدف: `Settings → Webhooks → Add webhook`

- **Payload URL:** `https://<رابطك>/api/github/webhook`
- **Content type:** `application/json`
- **Secret:** نفس `GITHUB_WEBHOOK_SECRET`
- **Events:** `push` فقط

### ٨) رسم الاعتماديات

محليًا:

```bash
npm run graph -- --dir ../المستودع-الهدف --repo owner/name
```

تلقائيًا عند كل push: انسخ `dep-graph.yml` إلى `.github/workflows/` **في المستودع الهدف**، وأضف السرّين `OPS_HUB_URL` و`GRAPH_INGEST_SECRET`.

## قرارات تقنية تستحق الانتباه

- **كل مفاتيح GitHub تبقى على الخادم.** توكن OAuth مُخزَّن مشفّرًا داخل كوكي `httpOnly`، ولا يصل المتصفح أبدًا. كل نداءات GitHub تمرّ عبر `/api/*`.
- **المتصفح يقرأ فقط من Supabase.** مفتاح `anon` مع سياسات RLS للقراءة فقط، ويُستخدم حصريًا للاشتراك في التحديث المباشر. كل كتابة تمرّ عبر مسار API يتحقق من الهوية والصلاحية بمفتاح `service_role`.
- **رسم الاعتماديات يُولَّد خارج التطبيق.** الدالة السحرية (serverless) لا تستطيع استنساخ مستودع، وتشغيل حاوية بناء يكلّف مالًا — لذلك يُولَّد الرسم عبر GitHub Actions (مجاني) ويُرسل إلى `/api/graph/ingest`.
- **الحجز لا يمنع أحدًا قسريًا.** يعرض التعارض بوضوح ويطلب تأكيدًا، لأن المنع الصلب في فريق صغير يخلق التفافًا حوله أكثر مما يحمي.

## التكلفة

كل شيء هنا على الخطط المجانية: Supabase (مجاني)، Vercel Hobby (مجاني)، GitHub API وActions (مجاني ضمن الحصة). لا توجد أي تبعية مدفوعة.

> **تحذير ترخيص مهم:** خطة Vercel Hobby مرخّصة للاستخدام الشخصي/غير التجاري فقط. لوحة العمليات أداة داخلية بلا إيرادات ولا مستخدمين خارجيين، فهي ضمن الشروط. **لا تنشر منتج المرحلة الثانية (الذي يبيع الأفاتارات) على Hobby** — استخدم Cloudflare Pages + Workers (يسمح بالاستخدام التجاري على الخطة المجانية) أو ارفع إلى Vercel Pro.

## ما لم يُبنَ بعد (من قائمة الأفكار الإضافية)

- إشعارات Discord/Telegram عند الحجز والفك.
- تصدير سجل التدقيق كملف.
- لوحة Issues/PRs بجانب كل ملف.
- مؤشر حالة آخر نشر للمنتج.

الأساس جاهز لكل منها: `audit_log` يسجّل الأحداث فعليًا، ومسارات `/api` قابلة للتوسعة مباشرة.
